# 入笼超额命运说明（当日锁死）

- 锁定日：2026-11-22（`backend/db.py: FREEZE_OVER_LIMIT_FATE_LOCKED_ON`）
- 采用路径：**乙路径**（`FREEZE_OVER_LIMIT_FATE = "乙"`）
- 适用范围：`POST /api/cages/freeze` 当金额超过账户可用额时的全部处置

## 为什么必须二选一且不得混用

两套口径若在同一天混用，会出现两种账面毒瘤：

1. 甲口径（只记审计拒入、余额够即可同日再入）被当成乙口径的「补丁」：
   拒入登记占着当日意图额度，但用户仍能直接再入 → 笼已建、账户冻结被抬高，
   登记却还在占额；对账若按登记判「当日已拒绝」就会假绿。
2. 乙口径的登记被甲口径绕过：正式笼零建时，对账只算活笼可用，于是账户冻结
   与笼面暂时相等，对账灯假绿，但拒入意图额度已被占住，第二笔合法入笼被挡。

因此本仓当日**只走乙路径**，并把该取舍写进代码常量与审计动作，任何偏离都会
被识别为「超额偏航」并拒绝写业务。

## 乙路径的精确定义

| 时点 | 正式笼 | 账户余额/冻结 | 拒入登记 | 审计 |
|------|--------|----------------|----------|------|
| 超额当次 | 零建 | 零改 | 落一条 `占额` 登记，占住当日意图额度 | `cage_freeze_rejected` |
| 同日再入（登记未撤销） | 零建 | 零改 | 保持不变 | `cage_freeze_deviation`（超额偏航） |
| 撤销登记 | 不变 | 不变 | 置 `已撤销` + 撤销人/时间 | `cage_freeze_rejection_revoke` |
| 撤销后再入且余额充足 | 正常建笼 | 冻结 +金额 | 无新增 | `cage_freeze` |
| 撤销后再入仍超额 | 零建 | 零改 | 新落一条 `占额` | `cage_freeze_rejected` |

- 「当日」按服务器本地日期 `YYYY-MM-DD` 判定（`now_iso()[:10]`）。
- 撤销仅限当日登记（`/api/cages/freeze-rejections/{id}/revoke`）。
- 拒入登记不是笼、不是冻结：`bond_accounts` 与 `cages` 都不因它变化，因此
  对账页必须把它单列，不能并入活笼可用，也不能并入账户冻结。

## 偏航判定

`backend/cages_svc.py: _fate_guard` 与「登记未撤销即再入」分支共同保证：

- 常量不是乙路径，或锁定日被改动 → 记 `cage_freeze_deviation` 并 409；
- 当日仍有 `占额` 登记却直接再入 → 记 `cage_freeze_deviation`（payload 含
  `超额偏航: true`）并 409。

## 与并发的关系（单独验收，不混入本说明的取舍）

两人同时对同一当事人入笼时，账户锁以**每请求唯一的持有者令牌**抢占并立即
落库；后到者只写 `contention_log`（动作「争用」），正式笼与账户零增。争用
口径不参与「甲/乙」命运取舍，两件事分开验收。
